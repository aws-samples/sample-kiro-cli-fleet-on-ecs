# bench-fanout

The load item for the M2~M5 benchmarks (`bench/fleetbench/fleetload.py`). It is the same work as
the M1 fanout run, so a fleet measurement can be read against the single-key curve: one
orchestrator, two subagents, fifteen 120-word notes each, about 37 tool calls per item.

The prompt each item carries is generated by `fleetload.item_prompt()` and sent through the
queue, which is how the fleet runs every workflow. This file is the reference copy of it:

```
You are an orchestrator. Use the subagent tool to start 2 subagents in parallel, in a single
response, with these assignments:
- Subagent A: read input/bench/fanout/notes/a-01.md through input/bench/fanout/notes/a-15.md
  and write output/summary-a.md
- Subagent B: read input/bench/fanout/notes/b-01.md through input/bench/fanout/notes/b-15.md
  and write output/summary-b.md

Tell each subagent: read its files one at a time, one file per read tool call, never several
files in one call, and read each file in full, from its first line to its last, never a line
range; then write a summary file listing, for each note, its title and its count, followed by
one sentence about the note.

Do not read the notes yourself. When every subagent has finished, read each
output/summary-*.md file and write output/final.md with the total of all counts. Then reply
with exactly: done
```

Every item reads the same corpus from the reference bucket (`bench/fanout/notes/`), uploaded
once by `fleetload corpus`. The correct total in `final.md` is fixed, so a result that read
every note can be checked without a model.

Deploy the fleet with `-c fleet:workflowPath=bench/fanout` to run it.
